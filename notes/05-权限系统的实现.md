# 实现方案


1. 设定权限管理类 PermissionManager， 用于检查和管理权限
2. 执行动作类型一般来源于具体tool， 所以在tool中加入权限声明 
3. 但是具体的Tool只负责声明权限，并不负责检查权限， 所以在Tools类中新增权限请求逻辑， 主要用于组装来自Tool的权限请求
    - 比如read的要访问文件，那么他的参数可能是相对路径也可能是绝对路径
    - 而权限的检查需要依赖绝对路径，所以Tools需要负责组装绝对路径，然后交给PermissionManager进行权限检查
4. 在Agent Loop调用工具前，先检查权限。
5. 如果权限是允许的， 即可调用对应的工具
6. 如果权限是拒绝的，则不能调用工具
7. 如果权限是询问用户，则应该暂停Agent Loop，询问用户，得到用户允许后，方可调用工具
8. 关于询问用户的回答： 
    * once allow 仅本次允许，不写入权限规则
    * session allow 本会话允许，写入规则，指定会话id
    * agent allow 本智能体允许， 也就是只要是这个智能体的调用，都允许，不分会话。
    * once deny 本次拒绝
    * session deny 本会话拒绝
    * agent deny 本智能体拒绝
9. 模式匹配
   * 目前支持三种模式： plan，build，yolo
   * plan 用于编写计划，不允许改任何文件
   * build 用于执行计划，或者对文件进行读写，但是受到权限约束，若无权限，则应该询问用户后继续
   * yolo 用于执行计划，或者对文件进行读写，不受权限约束，但受到强制安全权限的约束（有的命令和文件夹是绝对不允许访问的）
