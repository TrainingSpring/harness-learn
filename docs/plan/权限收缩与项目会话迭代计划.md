# 权限收缩与项目会话迭代计划

## 1. 目标

将权限从 Agent 的固有配置收缩为 Session 的运行约束。Agent 仅定义角色、LLM、指令与可用工具；一次 Session 决定项目目录、`plan/build/yolo` 模式和本会话的授权/拒绝规则。

本计划替代此前“当前 Agent 权限模式”和“Agent 级权限规则”的产品语义。旧文档保留为历史实现记录，不再作为后续接口依据。

## 2. 最终产品形态

### 2.1 用户看到的内容

1. 新建或打开会话后，输入框左侧有项目目录按钮。用户可选择一个本地项目目录，也可不选择直接开始普通对话。
2. 已选择目录时，输入区显示简洁的目录名或相对路径；目录选择按钮有可访问的提示文本。未选择时显示“未选择项目”。
3. Session 具有 `Plan`、`Build`、`YOLO` 三种模式。模式是会话设置，不属于 Agent；同一个 Agent 可同时参与不同模式的多个 Session。
4. 第一条用户消息成功写入 Session 后，项目目录永久锁定。界面显示锁定状态，不提供修改操作；避免工具历史、Session 授权和实际文件根目录发生错配。
5. 空项目 Session 仍可完整进行 LLM 对话；任何需要项目目录的文件或终端工具都返回稳定的 `PROJECT_NOT_SELECTED` 工具结果，不回退到服务器当前工作目录。
6. 权限弹窗固定提供四个清晰操作：
   - `仅本次允许`：只执行当前 `call_id`。
   - `本会话允许`：对同一 Session 的后续同类请求自动允许。
   - `拒绝`：只拒绝当前 `call_id`。
   - `不再询问`：对同一 Session 的后续同类请求自动拒绝。
7. Session 允许/拒绝规则在重新打开 Session 或服务重启后仍有效；不同 Session 绝不互相影响。硬安全策略始终优先，`YOLO` 和“本会话允许”均不能绕过。

### 2.2 领域归属

```text
Agent
  角色、LLM、提示词、工具集合

Session
  项目目录、权限模式、Session 授权/拒绝规则、共享 Context

Runtime
  读取 Session 权限策略执行 Agent Loop；仅保存运行中的 pending 调用与队列
```

`PermissionManager` 是 Session 的共享策略对象，不是 Agent 成员。GROUP Session 中各 Runtime 复用同一个 Manager，因而同一会话的授权和拒绝判断一致；不同 Session 必须各自构造 Manager。

## 3. 明确的业务语义

### 3.1 权限模式

模式只处理“没有命中硬安全、受保护资源、Session 规则时”的默认决定：

| 模式 | 项目内读取 | 项目内写入 | 终端执行 | 项目外资源 |
| --- | --- | --- | --- | --- |
| `plan` | allow | deny | deny | deny |
| `build` | allow | ask | ask | ask |
| `yolo` | allow | allow | allow | ask |

受保护系统路径始终为 `ask`，硬安全命中始终为 `deny`。`yolo` 不是“无条件越权”，而是对已选项目目录内普通操作的默认允许。

### 3.2 权限请求到协议字段的映射

保留现有 `PermissionResponse(call_id, decision, scope)` 形状，但收缩 scope 为 `once | session`：

| UI 操作 | `decision` | `scope` | 是否持久化 |
| --- | --- | --- | --- |
| 仅本次允许 | `allow` | `once` | 否 |
| 本会话允许 | `allow` | `session` | 是 |
| 拒绝 | `deny` | `once` | 否 |
| 不再询问 | `deny` | `session` | 是 |

`once` 不生成可复用规则，只作用于当前 pending 调用；`session` 规则按 `session_id + action + resource` 保存。对于 `bash.execute` 这类没有可可靠定位文件资源的动作，Session 规则覆盖该 Session 中同动作的后续终端调用；弹窗必须明确提示该影响范围。

### 3.3 项目目录与执行根

- Session 字段命名为 `project_path`，保存规范化绝对路径或 `NULL`；它是用户选择的项目根目录。
- `ExecutionContext` 使用 `project_path: str | None`，不再从 Agent 或状态数据库取得工作目录。
- 文件工具必须验证目标位于 `project_path` 子树内；没有项目目录、项目外目标或路径逃逸均不交给权限模式决定。
- 项目目录必须存在且为目录。选择后至首条用户消息前可替换；第一条 `USER_MESSAGE` 与目录锁定校验要放在同一事务语义内，活动 Run 或已有用户消息时返回冲突错误。
- 当前 Web 由本机 FastAPI 服务托管，目录选择器通过服务端逐级浏览本机目录；UI 不提供任意路径文本输入。API 接受目录选择器返回的相对或绝对目录路径，只允许真实存在的目录，并跳过软链接目录。

## 4. 现状与要删除的内容

当前实现存在以下 Agent 级路径，均要删除，不保留兼容分支：

- `AgentProfile.permission_mode`、`Agent.permission_mode`、Agent 表单/API 的 `permissionMode`。
- `AgentFactory` 对 `PermissionMode(profile.permission_mode)` 的解析，以及 `workspace`、`PermissionRuleRepository` 注入到 Agent。
- `permission_agent_rules` 表和 `PermissionRuleRepository`，以及 `PermissionScope.AGENT`、`PermissionRequest.agent_id`、`PermissionRule.agent_id`。
- 前端 `PermissionScope = "agent"`、`ScopeSelector` 中“当前角色/该角色允许”。
- `PromptBuilder` 从 AgentProfile 推导权限模式的后备逻辑。

不能把既有 Agent 级 allow/deny 规则迁移到任意 Session：它们没有安全可信的 Session 归属。迁移时删除该表，旧规则不再生效。

## 5. 实施顺序

各阶段均保持可测试、可提交。数据库迁移和领域模型必须先完成；前后端不可并行修改未确定的 API 契约。

### 阶段 1：迁移 Session 数据模型

   - `permission_mode TEXT NOT NULL DEFAULT 'plan'`，受领域模型严格校验为 `plan/build/yolo`。
   - `project_path TEXT NULL`，只存用户选择的绝对目录，不从它派生数据库位置。
2. 新建 `session_permission_rules`：`id`、`session_id`、`action`、`resource_kind`、`resource_value`、`decision`、`created_at`、`updated_at`；唯一键为 `(session_id, action, resource_kind, resource_value)`。
3. 删除 `permission_agent_rules` 表；重建 `agent_profiles` 表或等价迁移以删除 `permission_mode` 列。已有 Session 统一初始化为 `plan`、`project_path = NULL`。

5. 新增 `SessionPermissionRuleRepository`。它只接受 `SESSION` 规则，资源必须在 Session 的 `project_path` 下；`bash.execute` 的资源为 `None`。
6. 在 `SessionRepository` 新增原子更新方法：`update_project_path_before_first_message()` 与 `update_permission_mode()`。前者查询是否已有 `USER_MESSAGE` 并在同一事务内更新；后者拒绝活动 Run 期间修改。

### 阶段 2：收缩权限领域接口和纯策略

**目的**：从类型层禁止新的 Agent 级授权写入，并让策略明确以 Session 项目根为输入。

**改动**

1. 修改 `code/agent/permission/types.py`：
   - 删除 `PermissionScope.AGENT`。
   - 删除 `PermissionRequest.agent_id` 与 `PermissionRule.agent_id`。
   - `PermissionRule` 只允许 `SESSION` 身份；`PermissionResponse` 仍允许 `ONCE | SESSION`。
2. 修改 `PermissionManager` 构造器为 `mode`、`session_id`、`project_path`、`SessionPermissionRuleStore` 与硬策略依赖；不接受 Agent、Agent 仓储或数据库工作目录。
3. `PermissionManager.check()` 每次使用同一个 Session 规则集合，并按固定顺序判断：硬安全 -> 受保护资源 -> Session deny/allow -> 模式默认值。
4. `grant/deny()` 对 `once` 直接返回一次性处理结果，不写规则；对 `session` 先持久化成功再刷新内存规则，防止“数据库失败但本次运行认为已授权”。
5. 修改 `ModePolicy`：项目根为空时，文件/终端工具不由模式授权；项目外资源不因为 `yolo` 自动允许。保持硬安全和受保护目录优先。

**主要文件**

- 修改：`code/agent/permission/types.py`、`code/agent/permission/PermissionManager.py`、`code/agent/permission/policies.py`、`code/agent/permission/__init__.py`
- 修改：`tests/test_permission_types.py`、`tests/test_permission_manager.py`、`tests/test_permission_policies.py`、`tests/test_permission_persistence.py`

**验收**

- [x] 代码无法构造 `AGENT` scope、Agent 身份规则或 Agent 规则仓储。
- [x] 同一 Session 的允许和“不再询问”跨恢复有效；另一 Session 即使使用同 Agent 也不会命中。
- [x] 硬安全和受保护路径仍优先于 Session allow 与 `yolo`。

3. 修改 `code/agent/runtime/prompt_builder.py`：权限模式改由 `SessionService._open()` 作为运行时会话信息传入，或由 Runtime 追加为会话开发者消息；不可再从 AgentProfile fallback。

### 阶段 4：定义并实现 Web API 契约

**目的**：让前端只通过 Session API 读写会话设置，且不再看见 Agent 权限字段。

**改动**

1. 修改 Agent schema、路由和映射：删除创建、更新、详情返回中的 `permission_mode` / `permissionMode`。
2. 扩展 Session DTO：`permissionMode`、`projectPath`、`isProjectLocked`。创建 DIRECT/GROUP 请求允许传入初始 `permissionMode`，默认 `plan`；`projectPath` 不允许通过任意文本直接写入，必须由项目目录选择接口返回的已验证值或专用更新接口设置。
3. 新增 Session 设置接口：
   - `PATCH /api/sessions/{session_id}/permission-mode`，body 为受限模式枚举；活动 Run 时返回 `409`。
   - `PATCH /api/sessions/{session_id}/project`，body 为目录选择令牌或已验证目录 ID；首条用户消息后返回 `409 PROJECT_LOCKED`。
4. 新增项目目录浏览/选择接口。当前本机 Web 宿主允许从服务进程所在机器的目录树选择项目；接口只返回当前目录和直接子目录元数据，隐藏目录和软链接不进入列表。
5. 修改运行确认 DTO：`scope` 只接受 `once | session`；服务端对 `PermissionResponse` 做强校验，不信任浏览器提供的 action/resource/session。
6. 更新 `ChatService`、`RunRegistry` 和 SSE 映射，保持 `runId + sessionId + callId` 的恢复校验不变。Session 设置变更成功后使对应 React Query 缓存失效。

## 9. 风险与约束

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 旧 Agent 规则无归属地迁移 | 误把某 Session 的权限扩散到其他 Session | 直接废弃旧规则，不做推测性迁移 |
| Session 中多个 Runtime 缓存规则不同步 | GROUP 对同一请求出现不同决定 | SessionExecution 只创建一个共享 Manager |
| 未选项目时回退进程目录 | 空项目对话意外拥有文件系统权限 | 工具显式返回 `PROJECT_NOT_SELECTED` |
| 本机目录选择暴露过多路径 | 信息泄露或越权枚举 | 仅通过目录列表逐级浏览，不提供路径文本输入；服务端验证真实目录并跳过软链接 |
| 运行中修改设置 | 同一 Run 前后权限边界不一致 | 活动 Run、pending permission 时 API 和 UI 都拒绝变更 |

## 10. 实施前需确认

本计划对以下语义采用默认结论；请在实现开始前确认第一项：

1. **目录选择宿主**：当前实现采用本机 FastAPI Web 服务，目录选择针对服务进程所在机器。后续若部署为远程服务，应改为桌面壳原生目录选择器或配置允许的根目录列表，不能让远程浏览器选择服务端任意目录。
2. **“不再询问”默认结论**：本计划定义为“当前 Session 内，对同一动作和资源范围持久化 deny”。这与“本会话允许”对称，不影响其他 Session。
3. **模式变更**：本计划允许 Session 空闲时随时切换 `plan/build/yolo`，并对下一次 Run 生效；活动 Run 和权限弹窗期间禁止切换。如需首轮后也锁定模式，应在阶段 1 一并加锁，而不是由前端单独限制。
