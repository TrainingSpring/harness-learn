# 上下文与运行时架构更新迭代计划

## 1. 目标

本计划用于将当前项目调整为：

~~~text
Agent
= 独立、可复用的角色和能力定义

Session
= DIRECT/GROUP、成员关系、会话生命周期和 Context 的所有者

Context
= 一个 Session 的共享上下文，负责消息、工具结果、压缩、精简和恢复

Runtime
= Agent Loop，负责持续调用 LLM、处理工具和权限

ContextService
= 原始事件及当前实际 Context 的持久化
~~~

本计划只写文档，不代表代码已经完成。

## 2. 必须保持的不变量

1. Agent 不持有 Context、Session 或 ContextService。
2. 一个 Session 只有一个共享 Context。
3. GROUP 中所有 Agent 使用同一份 Context。
4. Runtime 保留 Agent Loop。
5. Runtime 通过 run(context) 使用 Context，但不将 Context 保存为实例属性。
6. Runtime 不直接访问数据库。
7. ContextService 不参与 Agent Loop。
8. 同一个 Agent 定义可以被多个 Session 使用。
9. 不同 Session 的 Context、ExecutionContext、Tools 执行环境和权限等待状态必须隔离。
10. 原始 context_items 不被压缩结果覆盖。
11. sessions.current_context_json 保存当前实际上下文。
12. DIRECT 和 GROUP 的差异由 Session 处理，不由 Agent、Tools、MCP 或 Skills 处理。

## 3. 当前实现基线

## 4. 生命周期模型

~~~text
AgentProfile
    ↓
AgentDefinition（可跨 Session 复用）
    ↓
Session A                         Session B
├── Context A                     ├── Context B
├── ExecutionContext A            ├── ExecutionContext B
├── Tools A                       ├── Tools B
├── Runtime 状态 A                ├── Runtime 状态 B
└── Permission 状态 A             └── Permission 状态 B
~~~

可以复用：

- AgentProfile
- AgentDefinition
- LLM 配置
- 工具定义和 schema
- Runtime 的执行算法

不能直接复用：

- Context
- ExecutionContext
- 绑定执行环境的 Tools
- pending permission
- tool queue
- 有状态 Runtime 实例

### 工作项

1. Runtime 构造器删除 Context 参数。
2. Runtime 构造器删除 ContextService 参数。
3. run(message) 改为 run(context)。
4. 用户消息由 Session 先写入 Context。
5. Runtime 内部继续保留 Agent Loop。
6. 每次继续请求模型前，从传入 Context 读取最新消息。
7. 模型消息、function call、tool output 都通过 Context 的公开方法追加。
8. Runtime 不直接写 ContextService。
9. Context 的事件回调或事件队列由 Session 交给 ContextService。
10. Runtime 不判断 DIRECT/GROUP。
11. Runtime 不决定下一个 Agent。

### 目标接口

~~~python
def run(
    self,
    context: Context,
) -> Generator[LLMResponse | PermissionRequiredEvent, None, None]:
    ...
~~~

### Runtime 内部流程

~~~text
读取传入 Context
    ↓
调用 LLM
    ↓
追加 Agent 输出
    ↓
追加 function call
    ↓
检查并执行工具
    ↓
追加 tool output
    ↓
再次读取同一 Context 的最新内容
    ↓
直到完成或等待权限
~~~

### 状态隔离

当前的 _state、_pending_permission、_tool_queue 不能跨 Session 共享。

迁移顺序：

1. 先放入 RuntimeExecution 或一次运行的局部状态。
2. 权限暂停时保留当前 RuntimeExecution。
3. 每个 Session 使用独立 RuntimeExecution。
4. 以后需要进程重启恢复时，再增加序列化。

### 验收

- [ ] Runtime 仍然执行完整 Agent Loop。
- [ ] Runtime 不保存 Context 实例属性。
- [ ] run(context_a) 只修改 Context A。
- [ ] run(context_b) 只修改 Context B。
- [ ] 工具结果影响下一次模型请求。
- [ ] 压缩结果影响下一次模型请求。
- [ ] Runtime 不访问数据库。

### 目标

SessionCoordinator 负责加载一个 Session 的运行环境，但不接管 Runtime 的 Agent Loop。

### 职责

- 加载 Session 元数据。
- 加载固定 Agent 成员。
- 创建一个 Context。
- 从 current_context_json 恢复 Context。
- 创建 ContextService。
- 创建 Session 级 ExecutionContext。
- 创建 Session 级 Tools 和 PermissionManager。
- 调用 Runtime.run(context)。
- 接收 Context 变化并交给 ContextService。
- 对 GROUP 进行外层 Agent 顺序调度。

### SessionExecution

建议新增：

~~~python
class SessionExecution:
    session_id: str
    conversation_mode: str
    context: Context

    def send(self, message: str):
        ...

    def resolve_permission(self, response: PermissionResponse):
        ...
~~~

SessionExecution 是运行中的 Session 环境，不等于 storage.types.Session。

### DIRECT 流程

~~~text
SessionExecution.send(message)
    ↓
Context.append_user_message(message)
    ↓
ContextService 保存用户事件
    ↓
保存 current_context_json
    ↓
创建当前 Agent 的 Runtime
    ↓
Runtime.run(context)
    ↓
Context 追加 Agent 消息和工具事件
    ↓
Context 治理
    ↓
保存 current_context_json
~~~

### GROUP 流程

~~~text
SessionExecution.send(message)
    ↓
写入共享 Context
    ↓
Runtime(Agent1).run(shared_context)
    ↓
治理并保存 shared_context
    ↓
Runtime(Agent2).run(shared_context)
    ↓
Agent2 读取 Agent1 的最新消息和治理结果
~~~

### 验收

- [ ] SessionCoordinator 可创建和恢复 SessionExecution。
- [ ] 一个 SessionExecution 只有一个 Context。
- [ ] Agent 不拥有 Context。
- [ ] ContextService 由 Session 创建和持有。
- [ ] DIRECT 可以发送和恢复。
- [ ] GROUP 可以顺序调用多个 Agent。
- [ ] Runtime Loop 仍在 Runtime 内部。

### 规则

- 一个 GROUP Session 只有一个 Context。
- 所有 Agent 读取同一个 Context。
- Agent 消息写入同一个 Context。
- Agent 根据 Context 自己判断是否发言。
- Agent 消息保留作者身份。
- Agent 按固定顺序串行运行。

- 并行 Agent。
- PRIVATE 消息产品语义。

作者格式由 Context 统一生成。

首期保存边界：

1. 用户消息进入 Context 后。
2. Agent 消息完成后。
3. function call 追加后。
4. function call output 追加后。
5. Context 治理完成后。
6. 权限暂停前。
7. Agent Loop 完成、失败或取消后。

首期并发限制：

- 一个 Session 同时只有一个活动 Run。
- GROUP 内 Agent 串行执行。
- 一个 Context 同时只有一个写入者。
- 不允许两个 Runtime 同时修改同一个 Context。

## 17. 不在本轮实现

- 每个 Agent 独立 Context。
- 每个 Agent 独立压缩。
- PRIVATE/TARGETED 完整产品语义。
- Agent 可见性投影。
- 并行 GROUP Agent。
- Stanford Town 自由对话调度器。
- Agent 长期记忆。
- Context Snapshot 历史表。
- 分布式 Session 锁。
- 进程重启后完整恢复 pending permission。
- 云同步和跨 workspace 同步。
